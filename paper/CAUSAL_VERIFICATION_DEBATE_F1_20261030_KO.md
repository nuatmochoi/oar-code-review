# 원인 검증·비평·소비 함수 탐색 비교 실험

2026-10-30 완료 · 기존 12개 + 프로젝트 미사용 12개 PR · 안전/결함 양방향 · 4조건 · 3반복 · **576/576 리뷰 완료**

**현재의 AST·LSP 본문 자동 보완을 유지하고, 새 조건의 전면 채택은 보류하는 것이 타당하다.** 비평·판정 조건의 원인 F1은 기존 사례에서 91.43%→92.75%로 소폭 높았지만 미사용 사례에서는 94.59%로 동일했다. 원인·반증 검증만 추가하거나 소비 함수 탐색을 우선한 조건은 두 사례군 모두 현재 방식보다 낮았다. 의미 있는 실패 원인은 확인했지만, 추가 기능이 안정적으로 성능을 높였다는 근거는 부족하다.

특히 이번 비평 조건은 반박 내용 일부가 마지막 판정에 전달되지 않았다. **전체 비평을 보존하는 multi-agent debate의 효과를 검증한 결과로 일반화할 수 없다.** 실행 도중 이를 바꾸지 않고, 동결된 구현의 결과와 후속 수정 가설을 분리했다.

## 비교한 기능과 평가 기준

공통 기준은 **AST·native LSP 문맥 + 실제 전달된 본문을 추적하는 자동 보완 + 재검토**다. 이것이 이번 표의 첫 행이며, diff만 주는 기준선과는 다르다. 원인·반증 검증에서 비평·판정과 소비 함수 우선 탐색이 각각 갈라진다. 두 기능을 합친 조건은 이번에 실행하지 않았다.

PR·방향·반복마다 최초 응답을 새로 생성해 네 조건이 공유하고 후속 판단 두 번은 각각 독립 호출했다. `gpt-5.6-sol`, reasoning `low`, 조건당 3회 판단, 초기 준비 포함 조회 6회, 전달 소스 합집합 5,200 reference tokens, 메타데이터 800, 판단 상태 1,600을 공통 상한으로 했다. 4개 작업을 병렬로 진행했고 호출 시작 간격은 최소 3초였다. 같은 상한이 동일한 실제 토큰 사용량을 뜻하지는 않는다.

원인 정탐은 **고정 입력에서 정확한 실패 연산과 영향을 지적했는가**, 근거 정탐은 **그 원인을 입증할 호출·타입·소비 연결이 실제 모델 입력에도 있었는가**를 평가한다. 평가자가 저장소에서 읽을 수 있다는 이유로 모델에 전달되지 않은 본문을 근거로 인정하지 않았다.

`정밀도 = TP / (TP + FP)`, `재현율 = TP / (TP + FN)`, `F1 = 2TP / (2TP + FP + FN)`이다. F1은 정밀도와 재현율의 조화평균이다. 결함 방향·반복마다 TP는 최대 1개이고, FP는 최종 finding 수에서 TP를 뺀 수다. 동일한 목표 결함을 두 지적으로 나눈 경우 추가 보고도 FP에 들어간다. 안전 PR 오경고와 구분해서 해석해야 한다. 최종 호출 실패는 앞 응답으로 대체하지 않는 기준을 적용했으며, 이번 최종 실패와 명시적 판단 유보는 모두 0건이다.

## 성능을 막은 구현상의 지점과 후속 순서

**첫째, 비평의 핵심을 판정자에게 보존해야 한다.** 비평자는 `observations`에 반박을 쓰도록 지시받지만 현재 전달 요약은 `candidates·findings·context_requests`만 담는다. `review.summary·observations`는 직접 전달하지 않고 최초 주장 원장도 그대로 유지한다. 따라서 finding을 철회하고 observation에만 반박하면 그 이유가 사라질 수 있다. 실제 비평 전달 진단에서 이 누락을 실제 입력으로 확인했다.

판정 상태의 예산 절단도 남아 있다. 비평 조건의 288개 후속 상태 중 최초 원문 발췌는 250개, 직전 응답 요약은 45개, 주장 발췌는 107개, 의미 검사 발췌는 5개에서 잘렸다. 바깥 JSON은 유효했고 실제 입력과 해시도 일치했다. 이는 이전 답변·상태 발췌의 문제이며 소스 본문이 다시 12,000자에서 잘렸다는 뜻은 아니다. N03의 핵심 검사 결과는 전달 여부를 별도로 확인했다. 상태 전달 감사.

**둘째, 의미 검사를 최초 자연어의 이름 목록에만 묶지 않아야 한다.** N11은 실제 `ast.Name` 소스를 갖고도 최초 주장에서 추출한 식별자 목록이 비어 검사 허용 조건을 통과하지 못했다. 신규 주장과 실제 소스 연산을 연결하고, 지원 불가·실행 실패·실행된 반증을 서로 다른 상태로 보존하는 수정이 필요하다. 검사 환경 제한을 없애자는 제안은 아니다. N11 검사·오경고 진단.

**셋째, 소비 함수 일반 우선순위보다 현재 원인에서 빠진 연결을 우선해야 한다.** 현 구현은 `self.args`와 지역 `args`, 필드 `i`와 반복 변수 `i`를 같은 문자열로 묶을 수 있다. 넓은 클래스의 다른 속성까지 탐색 초점에 합쳐지고, 짧은 guard에 조회를 먼저 써 생성자·protocol이나 native 위치 조회를 위한 예산이 소진된다. receiver·scope·정의 위치를 구별하고 필요한 위치 조회와 본문 획득 예산을 예약하는 후보가 더 타당하다. H10에서는 이미 만들어진 tuple의 소비자보다 고정 입력의 dispatch와 예외 처리 연결이 필요했다. 소비 함수 선택 진단.

이번 결과를 보존한 채 **비평 전달 수정 → 검사 연결 수정 → 빠진 호출·타입·예외 연결 우선 탐색**을 각각 분리 비교하는 것이 다음 순서다. 수정은 아직 이번 실험에 적용하지 않았고 향상을 보장하지 않는다. 같은 24개로 회귀를 확인하되, 이들은 이제 모두 사용 이력이 있으므로 채택 판단에는 새로운 미사용 PR이 필요하다. 후속 실험 가설.

## 실제 실행과 비용

본실험의 물리 호출 시도는 **1,304회**, 재시도는 **8회**다. 공유 최초 응답 144개는 실제 총량에서 한 번만 센다.

## 보존·검증 및 해석 범위

완료했던 응답을 그대로 두고 남은 단계만 실행했다. 중단 시점의 결과 파일 **5,504개**, 기존 채점 파일 **4개의 원본 접두 바이트**, 관리용 보존 파일 **7개**의 해시 검증이 통과했다. 동결 코드·의존성·공개/비공개 workspace·기존 제품 스냅샷 감사도 통과했으며 이번 감사에서 추가 확인한 파일은 **119,549개**다. 중단 전 자료 보존 감사, 전체 원본 보존 감사.

평가는 공개 Python PR의 작은 양방향 과제이고 공개 계약을 입력으로 제공했다. 추가 12개는 고정 seed로 선택한 Django 6개·Sympy 6개이며, 이 프로젝트에서 미사용했다는 뜻이다. 모델 학습에서 보지 못한 자료라는 뜻은 아니다. 조건명을 아는 AI 평가자가 채점했고 일부 경계 사례만 별도 판독했으며 독립 인간 검증은 수행하지 않았다. 실제 고객 MR 전체, 다른 언어, 고객이 말한 Python 개선을 재현했다고 주장할 수 없다. 10월 29일 중단 후 30일 재개해 일부 대응 분기의 실행 시점이 달라 공급자 측 시간 변화도 완전히 제거하지 못했다.
