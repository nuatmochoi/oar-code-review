# 상태 예산 분리 진단: 예산을 늘리면 탐지가 회복되는가

2026-10-30 완료. **이번5PR 진단에서는 상태 예산을1,600에서5,120으로 늘려도 수정 전달 방식의 탐지가 회복되지 않았다. 원인 F1은30.00%→21.05%, 정탐은3→2회였다. 단순 상태 예산 확대의 우선순위를 낮추고, 비평이 지적한 누락 본문을 확보하는 탐색을 다음 구현의 우선 대상으로 삼는다.** 이 결과가 모든 예산 제약의 영향 부재를 증명하는 것은 아니다.

이번 실험은 직전 탐지 손실이 관측된5PR만 고른 진단이다. 이전 전체24PR의84.85%/91.67%와 직접 비교할 수 없다. 두 방향·모든 저장3반복을 포함했고, 네 조건 모두 마지막 답변을 새로 생성했다. 과거 점수를 대조군으로 재사용하지 않았다.

## 네 조건의 결과

5PR × 안전/결함2방향 × 저장3반복 × 4조건 = **120개 새 응답·120개 채점**이다. 조건당 결함15개·안전15개다.

| 전달 방식·상태 상한 | 원인 TP/FP/FN | 정밀도 | 재현율 | 원인 F1 | 근거 TP | 근거 F1 | 안전 PR 경고 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 기존 비평 전달 · 1,600 | 10/1/5 | 90.91% | 66.67% | **76.92%** | 3 | 23.08% | 0/15 |
| 수정 비평 전달 · 1,600 | 3/2/12 | 60.00% | 20.00% | **30.00%** | 2 | 20.00% | 0/15 |
| 기존 비평 전달 · 5,120 | 10/1/5 | 90.91% | 66.67% | **76.92%** | 3 | 23.08% | 0/15 |
| 수정 비평 전달 · 5,120 | 2/2/13 | 50.00% | 13.33% | **21.05%** | 2 | 21.05% | 0/15 |

원인 TP는 정확한 입력 조건·실패 연산·영향을 최종 finding으로 보고한 경우이며 PR·방향·저장반복당 최대1개다. FP=raw finding−TP, FN=결함 평가 수−TP, F1=2TP/(2TP+FP+FN)이다. 근거 TP는 원인 정탐에 더해 필요한 소스 연결이 실제 입력에 있어야 한다. 이전 모델의 주장은 소스 근거가 아니다. 모든 조건의 실패·명시적 보류·안전 오경고는0개다.

주 비교는 **같은 수정 builder에서 cap만 바꾼5,120−1,600**이다. 새로 회복한 원인 정탐0회, 잃은 정탐1회, 결함 방향 동일14회였다. 기존 전달 정책은 합산 F1이76.92%로 같았지만, 개별적으로는 회복2회와 손실2회가 상쇄됐다. 충분 예산에서 두 전달 정책의 차이는 내용 선택·전달 정책도 다르므로 비평 본문 하나나 형식만의 효과로 표현하지 않는다.

수정 방식의 근거 F1은20.00%→21.05%지만 **근거 TP는2회로 동일**하다. 보고 수가5→4로 줄어 분모가 작아진 결과이며, 원인 정탐 감소를 동반한다. 근거 탐지가 좋아졌다고 해석할 수 없다. 반복·PR별 전체 표, 전체 집계 JSON.

## 예산을 어떻게 분리했나

**1,600/5,120은 이전 판단·비평·검사 결과를 담는 상태 블록의 상한**이다. 전체 모델 문맥이나 소스 조회 예산이 아니다. 코드·diff·조회 결과·probe 원본·역할·판정 지시·응답 schema를 고정하고 상태 블록 밖 실제 입력을 전수 비교했다. 새 소스 조회나 probe 실행은 없다.

| 조건 | 유지한 정책 | 예산에서만 바꾼 부분 |
|---|---|---|
| 기존1,600 | 직전 legacy 실제 입력 그대로 | 없음 |
| 수정1,600 | 직전 repaired 실제 입력 그대로 | 없음 |
| 기존5,120 | 같은 digest의 필드 선택·중복 제거 | 내부600 및 외부1,600에 의한 제외/절단 해제 |
| 수정5,120 | 같은 항목 선택·우선순위·정책 제외 | builder의 cap만 증가 |

기존full은 비평 summary/observations를 새로 추가하지 않는다. 수정full은 초기 observations의 중복 제외 및 protocol roots의 구조적 제외를 유지한다. 따라서 full은 **각 정책이 허용하는 내용의 완전 전달**이며 전체 transcript 전달은 아니다. 초기 응답 전체와 비평 digest를 담는 기존 정책과 특정 필드를 고르는 수정 정책은 충분한 예산에서도 포함 내용이 다르다.

모델 호출 전에30prefix의 양 정책 내용을 모두 생성해 최대4,604 reference tokens를 측정했다. 이를1,024단위로 올림하고 greedy 배분의 중간 omission 목록까지 고려해 공통 cap5,120을 고정했다. 60개full 상태의 허용 record/leaf 모두 완전 전달, 예산 누락/절단0개, 차단0개를 확인했다. 낮은 예산60개는 직전 실제 입력과 바이트 동일했다. 최종 합성 입력의 최대 reference token 수는13,670이었다. 120개 전달 검증, [상태 생성 코드](../runs/handoff_budget_diagnostic_20261030/budget_states.py), 동결 명세.

| 전달 방식·상태 상한 | 실제 상태 평균 | 실제 최소–최대 |
|---|---:|---:|
| 기존 비평 전달 · 1,600 | 1441.7 | 982–1594 |
| 수정 비평 전달 · 1,600 | 1322.7 | 912–1600 |

상한을5,120으로 올렸다고 매번 그만큼 채운 것은 아니다. 실제 길이·provider 비용은 조건마다 달라 동일 계산량 실험이라고 부르지 않는다. 추가 토큰에는 최초 finding·주장·critic 부가 필드·probe 상세 등 각 정책이 예산 때문에 덜 전달했던 내용이 포함된다. 그 중 어떤 필드가 원인인지까지 분리한 실험은 아니다.

## 이전6손실은 회복됐나

직전 손실6회는 N03_a_r1, N06_b_r1/r2, N07_a_r1, H05_b_r3, H10_a_r1이다. 이번 새 낮은 예산에서 그 손실 패턴이5회 재현됐다. 그5회는 수정full에서도 모두 미탐이었다. 나머지 H05_b_r3은 이번 새 수정low에서는 정탐이었고 full에서 미탐으로 바뀌었다. 따라서 과거 점수와 비교해 회복을 부풀리지 않는다. 원래6묶음에서 수정full의 원인 정탐은0/6이며, **신규 low→full 회복은0회·손실1회**다.

| 사례 | 실제 새 출력·입력에서 확인한 점 |
|---|---|
| N03 decorator | 충분 예산에서 최초 지적·claims·비평·검사 상세를 보존해도 수정full은 wraps 내부의 metadata 복사 실패라는 오원인을 유지했다. 실제 실패는 사용자 wrapper의 f.__name__ 접근이다. 기존full은 r1에서 정확한 원인을 설명했다 |
| N06 가정 보존 | 양수성→유한성 추론·질의 본문을 확보하지 않은 채 비평이 그 공백을 지적한다. 이전 주장 전체를 전달하는 것만으로 새 소스가 생기지 않았다 |
| N07 rank-zero 배열 | 수정 두 예산은 세 반복 모두 __len__ 및 scalar 정규화 연결 부족으로 무경고다. 기존full은 새 r2/r3에서 정확한 국소 원인을 보고했으나 실제 소스 연결이 빠져 근거 TP는0이다 |
| H05 언어 경로 r3 | 새 수정low의 정확한 regex 지적이 full에서 reference로 내려갔다. 핵심 비평 본문·summary·최초 finding·finding claim은 두 예산에서 이미 같았다. full 추가분은 부가 필드·추천·evidence note·중복 observation claim 설명이다 |
| H10 evalf | 최초 지적·비평·claims를 충분히 보존해도 수정 두 예산은 고정 Mul/Max 입력의 fallback 도달 근거 부족으로 경고하지 않았다. dispatch·성분 분해·상위 예외 처리 본문은 소스에 추가되지 않았다 |

기존 정책의 예산 확대는 N07_a_r2/r3의 원인 정탐을 회복했지만 N06_b_r1/H10_a_r2에서 원인 정탐을 잃었다. 따라서 예산 영향 자체가 전혀 없다고 결론낼 수 없다. 다만 **원래 수정안의 손실을 단순 예산 확대로 해결한다는 가설은 이 진단에서 지지되지 않았다.**

사례의 출력 비교는 N03/N06 판독, N07 판독, H05 판독, H10 판독에 있다. N03/H05 일부 경계는 부모가 원문을 별도로 판독했고 판정과 SHA를 보존했다.

## 불확실성과 해석 범위

주 비교 수정full−수정1,600의 원인 F1 차이는 **-8.95%p**, PR5개 군집 bootstrap95% 구간은 **[-23.81, +0.00]%p**다. 재현율 차이는-6.67%p, 구간[-20.00, +0.00]%p다. PR 단위로 양방향·모든 저장반복·조건을 함께10,000회 재표집했다(seed2026103012). 작은 결과 선택 표본의 조건부 탐색적 구간이며 일반적인 악화 확정 검정이 아니다.

사례 선택은 직전 결과를 본 뒤 이뤄졌고 모두 공개 Python PR의 재사용이다. 새1,600 응답으로 대조해 과거 점수 재사용과 회귀-평균 혼동을 줄였지만 선택 편향을 없앤 것은 아니다. 초기/비평은 고정된 역사 자료이고 새 전체 파이프라인을 반복한 실험이 아니다. 공개 계약을 제공했고 조건을 볼 수 있는 AI가 수동 채점했으며 일부 경계만 별도 AI가 교차 판독했다. 독립 인간 검증과 실제 고객 MR 검증은 없다.

## 실행·비용·보존

신규 물리 호출 **120회**, 재시도0회, 최종 실패0회, 사용량 미보고0회다. 입력 **2,445,942토큰**, 출력 **181,765토큰**이 관측됐다. cached입력1,102,592과 reasoning출력24,924은 각 입력/출력의 하위 항목이므로 다시 더하지 않는다. 과거 초기/비평/조회/probe 및 설계·채점 에이전트 비용은 신규 합계에 넣지 않았다.

모델은gpt-5.6-sol·reasoning low, 동시4개·시작 간격3초다. 호출 순서(seed2026103011)와 코드·입력·분석을 결과 관측 전에 동결했다. 집계 합성 테스트43개가 통과했고, 모든120 결과·채점이 완성되기 전에는 전체 F1을 계산하지 않았다. 응답 내용이 틀렸다는 이유로 재호출하지 않았다. 실제 모델 도구 호출은0개다.

직전 완료 결과5,697파일과 그 이전 결과19,982파일 및 import 의존성11개의 실행 전후 해시가 그대로였다. 새 응답·채점·입력은 별도 run에 저장했다. 실행 감사, 보존 감사, 집계 검증, 독립 수치 검토.

## 다음 구현의 우선순위

기계적 예산 증가는 성능 기본값으로 채택하지 않는다. 다음은 **비평의 ‘근거 부족’을 필요한 본문 조회로 연결한 뒤 재판정하는 탐색**이다. 부족한 연결을 확인하지 않고 경고만 지우거나, 이전 모델의 긴 주장을 소스 근거로 승격하지 않도록 한다.

구체적 목표는 N06의 추론/질의, N07의 길이 소비자, H05의 경로 소비 함수, H10의 dispatch·성분 분해·상위 예외 처리다. N03에는 실제 실패 연산과 probe가 검사한 연산의 구분도 필요하다. controller가 부족한 연결과 실제 전달 완료 여부를 추적하도록 하고, 현재 새 대조군과 동일 초기 소스·조회 예산으로 비교한 별도 실험이 필요하다. 이 탐색 수정과 의미 검사 연결 수정은 이번 결과에는 포함되지 않는다.
