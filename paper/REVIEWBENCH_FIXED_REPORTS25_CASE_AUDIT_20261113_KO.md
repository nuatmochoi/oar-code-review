- **보고 상한이 검토 기회를 막은 사례.** `apilix`에서는 두 조건 모두 미저장 변경을 반영하지 않고 작업공간을 전환하는 경로의 정답 행을 `B012`로 확보했지만 기존 보고가 6개여서 생성 호출을 건너뛰었다. 상한에 걸린 5개 PR의 기존 미탐 93개 중 재조회 원문과 공식 정답 행이 겹친 사례는 이 1개였다. `PROTRIDER`는 앞선 전체 리뷰에서 연결 순위가 배열 입력 호환성 결함을 찾았다. 이번에는 상한으로 생성을 건너뛰었고, 재조회로 선택한 `B017`에는 그 함수가 없었다. 상한 해제의 효과는 이 기록으로 확정할 수 없다. apilix 실행 기록 · PROTRIDER 이전 후보 기록
- **재조회 범위에서 빠진 사례.** `disaster-ninja-fe`에서 앞선 전체 리뷰는 레이어를 다시 붙이는지 확인한다는 테스트가 해제 호출만 검사하는 문제를 찾았다. 이번 후보 생성 입력에는 해당 테스트의 핵심 행이 없었다. `wirechat`에서도 앞선 전체 리뷰가 찾은 느린 미디어 로드 후 자동 스크롤 결함의 인용 행이 이번 후보 입력에 없었다. disaster-ninja-fe 후보 입력 · wirechat 이전 후보 기록
- **원문을 받고도 후보로 내지 않은 사례.** `gimmes`에서는 두 조건 모두 테스트 도우미가 누적 거래량과 24시간 거래량을 같은 값으로 설정하는 행을 `B006`으로 받았으나 후보 배열이 비어 있었다. 공식 정답은 최근 거래량이 0이고 누적 거래량이 양수인 경우의 테스트 누락을 지적한다. 이 한 행만으로 해당 조건의 동작까지 입증됐다고 볼 수는 없다. `chronicle`의 9개 질문 해결은 이전 재조회 실험의 답변 판정이다. 이번 추가 후보 호출은 빈 배열을 반환했다. gimmes 재조회 기록 · gimmes 후보 출력
- **결합 판정이 갈린 사례.** `node-postgres`의 두 후보는 실패 후 테스트 구독이 남는 문제를 다뤘다. 의미 검색 후보는 테스트 간 영향이 입증되지 않았다는 이유로 제외됐다. 연결 순위 후보는 더 앞선 행을 인용해 연결 오류 시의 조기 종료까지 짚었고 목록 밖 정탐으로 채점됐다. `wirechat`의 읽음 표시 후보는 기존 템플릿 조건문이 주장을 반박했다. `Mcp-Docker` 연결 순위 후보는 연결한 질문의 재조회 블록에서 인용 전체를 찾지 못해 결합 전에 탈락했다. node-postgres 의미 검색 결합 · 연결 순위 결합

후보 생성 요청은 실행된 17개 PR 중 10개에서 두 조건이 동일했다. `fastimage`와 `emdash`가 여기에 해당하며, 각각 독립 모델 호출에서 후보 수가 달랐다. `fastimage`의 공통 정답은 같은 재조회 원문으로 설명된다. EXIF 추가 보고와 `emdash` 오탐의 차이를 연결 순위의 효과로 귀속할 근거는 없다. 위 진단은 저장된 입력·출력과 공식 모델 채점을 대조한 사후 분석이다. 공식 결과와 실험 명세
