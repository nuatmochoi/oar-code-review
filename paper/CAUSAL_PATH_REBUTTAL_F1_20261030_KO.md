### 구현한 변경

- 공급된 코드의 receiver·lexical owner·import·실제 call/catch 관계로 native 후보를 좁혔다. native 반환을 파일 읽기 전에최대8개 선택하고 원 반환값의 변경 없는 부분집합인지 검사한 뒤 hash를 확인한다. 이후 실제 scope 관계를 다시 검사해최대2개 본문 후보만 selector/fallback에 전파한다.
- selector는 초기 공급파일 외 신규 index파일12개, fallback은 총 index파일12개로 제한했다. 마스킹된 문서·빈 줄보다 실행 구간을 우선 읽고 같은 unit의 남은 실행 구간을 이어 읽는다. 실행 구간 확보와 전체 행 body 완료를 구별한다.
- 검증자는 실패 연산·직접 소비자·선행 guard·예외 소비자·대안 원인·countercase를 분리한다. verified/contradicted 등의 표시는 **모델 의견**이며 controller가 정답으로 확정하거나 finding을 강제 제거하지 않는다. controller는 schema와 실제 인용 ID·경로·행만 확인한다.
- 이번 반증은 **소스 기반 모델 검토**다. 대상 PR의 신규 반례 코드/프로브는 실행하지 않았고 countercase는 실행되지 않은 예측으로 표시했다. 검증자의 말이나 language_rule 주장을 새 repository source로 등록하지 않았다.

새 경로 수집은 native+본문 합계최대6회, chunk최대200행, 누적 HEAD+BASE source5200 reference tokens다. 기존 근거·ID·내용을 삭제·압축·퇴출하지 않았다. 원래 상태cap5120과 기존 metadata cap800을 보존했다. 검증자에는 별도 source inventory가 추가되므로 **검증자 입력 전체 metadata가800 이하라는 뜻은 아니다**. 실제 inventory는 기존 조건280~2775, 새 경로 조건280~2181 reference tokens이며 provider 입력에 모두 포함했다.

검증 feedback은 wrapper/최종 안내를 포함해1800 reference tokens로 제한했다. 정책을 실제 데이터 조회 전에, 코드·입력·채점 계약을 모델 전에 고정했다. 결과를 본 뒤 검색 정책/지시를 수정하거나 좋은 응답만 재실행하지 않았다.

### 3.1 반증자가 잘못된 원인을 인증한 사례

N03_a_r2_rebuttal에서 검증자는 `wraps(f)`가 누락된 `__name__`을 복사하다 AttributeError를 낸다는 설명을 verified로, 올바른 후속 사용자 wrapper의 `f.__name__` 접근 실패를 contradicted로 기록했다. 최종 finding도 잘못된 실패 연산을 채택했다.

실제 stdlib의 wraps/update_wrapper는 복사할 속성이 없으면 AttributeError를 건너뛴다. 목표 실패는 이후 호출된 사용자 wrapper가 captured partial의 `f.__name__`을 직접 읽는 연산이다. controller의 인용 검사는 모두 통과했지만 인용한 Django 코드는 이 잘못된 functools 동작을 입증하지 않는다. **유효한 source ID·행과 의미적으로 올바른 검증은 별개다.** 같은 모델이 역할만 바꿔 검토해도 공유하는 API 오해를 강화할 수 있다.

이 회차 feedback은1540토큰, 핵심 완전 전달, 생략 필드0이었다. 따라서 이 사례를 예산 잘림이나 비평 전달 누락으로 설명할 수 없다. countercase도 이름을 복원한 대체 상태를 가정한 예측일 뿐 현재 head의 실패 연산이 실제로 통과하거나 실패했다는 관측 자료가 아니다. 부모가 원문과 grader-only stdlib source를 독립 대조했다. 이 stdlib 자료를 모델에 공급했거나 실행 probe를 수행했다고 세지 않았다.

### 3.2 실제 caller는 찾았지만 마지막 경로가 빠졌다

H10 unsafe의 새 세 prefix에는 EvalfMixin.evalf1340–1419가 실제 전달됐다. NotImplementedError를 잡는1395–1407과 결과 tuple 소비를 확인했다. safe b_r1/r2도 해당 caller를 받았다. 이전 임의 Product/atan/다른 모듈의 예외 함수만 읽던 상태보다 관련성이 개선됐다.

그러나 a_r1은 evalf_table의 Mul→evalf_mul 바인딩까지만 읽고 **evalf_mul 본문과 인수별 재귀 경로**를 읽지 못했다. a_r3의 _random/is_constant는 고정된 직접 evalf 호출의 경로가 아니다. b_r3도 공개 caller를 못 받았다. 새 응답은 미초기화 정밀도 위험을 reference로 설명했지만 최종 findings를 비웠다. caller를 얻었다고 전체 고정 입력 경로를 닫은 것으로 세지 않았다.

### 3.3 외부 base와 동적 규칙 연결이 남았다

N07의 class header에는 외부 NDimArray base 사용이 보이지만 현재 protocol 탐색은 같은 파일에 이미 index된 base를 따라가는 수준이다. **외부 base의 실제 사용 위치→native 정의→정확한 protocol member 본문**으로 이어가는 locator가 아직 생성되지 않는다. 해당 경계를 일반적인 동명이인 검색으로 대체하지 않았다. 현재 a_r3은 세 조건의 base 전체와 일반 verifier 입력까지 같아 이 회차를 새로운 경로 탐색의 성과로 귀속할 수 없다.

N06은 새 StdFactKB208–231을 안전 a_r2에서만 받았다. 사실 저장과 deduce_all_facts 호출은 보이지만 실제 finite 규칙·질의는 없다. unsafe 방향의 Wild나 posify 소비 호출부는 가정 엔진을 대신하지 않는다. 현대 Sympy에 대한 모델 기억이나 검증자의 verified를 이 저장소 source로 채우지 않았다.

H05의 docstring-only 빈 행 생략은 필요한 match508→if509→None510 실제 실행 분기를 전달했는지 직접 확인해 채점했다. whole-unit 완료 flag가 아니라 동결된 좁은 충분 근거 경계를 적용했다. 안전 방향은 여전히 실제 check_for_language 반환 guard의 참 값이 확인되지 않아 충분한 안전 근거로 승격하지 않았다.

## 5. 채택 판단과 다음 수정

현재 결과로는 **경로 선택+source-only 반증을 기본 구성으로 채택하지 않는다.** 동일 예산 주 비교에서 원인/근거 F1·재현율·FP가 모두 같고, 잘못된 API 동작을 반증자가 자신 있게 인증하는 실패도 확인했다. 기존 탐색보다 낮은 관측 점수는 동일 입력의 생성 변동과 분리해 해석한다.

보존할 개선점은 실제 caller/catch의 확보, 후보 fan-out 제한, source/의견/실제 전달을 분리한 감사다. 다음 우선순위는 모델 역할을 더 늘리는 것보다 아래 두 연결이다.

1. **실제 보이는 미완성 edge를 끝까지 잇는다.** 외부 base의 사용 위치에서 LSP 정의와 protocol member를 연결하고, dispatch table의 함수 값 바인딩에서 해당 callee 본문과 필요한 재귀 호출까지 이어간다. N07의 외부 base, H10의 evalf_mul, N06의 가정 규칙/질의가 구체적인 미완성 edge다. 필요 없는 caller 목록을 더 읽거나 예산만 늘리는 것으로 대체하지 않는다.
2. **실패 연산의 반증을 실제 계약/관측으로 확인한다.** 외부 API의 원문 계약이나 고정 입력을 유지한 최소 실행 검증을 사용해 decorator 생성과 후속 wrapper 호출 같은 서로 다른 연산을 구별한다. 입력/상태를 바꾼 예측 countercase와 실제 반례를 분리한다. 이 실행 검증은 이번에 하지 않았으므로 후속 가설로 남긴다.

그다음 같은 개발 사례에서 정책을 고정하고 전체12개·새 미사용 사례로 확장하며, 같은 입력에 대한 신규 verifier/final 반복도 추가해야 한다. 현재5PR 결과로 일반 코드 리뷰·다른 언어·실서비스 성능이나 새로운 논문 method의 우월성을 주장하지 않는다.

참고로 직전 *검증 호출 없이* gap source로 final만 생성한 진단은 원인 F1 52.17·근거 F1 34.78·재현율40.00%·FP2였다. 이번54.55와 비교해 일반 검증 추가의 인과 효과를 주장할 수는 없다. 호출 예산·새 응답이 달라진 과거 참고값이며, 이번 동일 예산3조건 비교가 채택 판단의 기준이다.
