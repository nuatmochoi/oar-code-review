# 코드 리뷰 아이디어 1·2 병렬 파일럿

2026-09-28. **SwingArena에서 가져온 실행 근거와 MCR-bench에서 가져온 라운드별 결함 메모리를 두 트랙으로 병렬 실행했다.** 최종 유효 모델 호출은 52회이며 모두 관측된 도구 호출 0회다. 실행 가능한 리뷰 테스트는 만들 수 있었지만, 메모리의 정확도 개선이나 SCIP의 고유한 우위는 이번 표본에서 확인하지 못했다.

모델은 `gpt-5.6-sol`, reasoning `low`, 조건별 생성 1회다. Swing은 기존에 관찰한 개발 사례 2개, MCR은 공개 데이터의 PR 3개만 사용했다. 논문 전체 재현이나 방법 간 우월성 검증이 아닌 탐색 파일럿이다. 두 트랙은 데이터와 과업이 다르므로 점수를 합산하지 않는다.

## 1. 문맥 검색 → 리뷰 → 실행 가능한 반례

Click pager와 AnyIO backend options의 정상·결함 변형에 네 가지 문맥 조건을 적용했다. 총 16회 생성이며, 검색 소스 예산은 최대 800 `o200k_base` 토큰이다. AST 구문 BM25는 SwingArena의 CodeBERT 재정렬을 재현한 방법이 아니다.

모델이 만든 테스트를 수정하지 않고 각각 `safe_base`, `unsafe_base`, `safe_head`, `unsafe_head`에서 두 번씩 실행했다. 앞의 세 대조 환경은 통과하고 결함 head에서만 실패해야 유효하다. 단순 실행 오류나 시간 초과는 확정 반례로 세지 않았다.

| 문맥 조건 | unsafe의 정확한 원인 지적 / 2 | 전체 입력에서 생성한 유효 회귀 테스트 / 4 | 자신이 리뷰한 unsafe 패치의 반례 / 2 |
|---|---:|---:|---:|
| diff만 | 1 | 1 | 0 |
| 60줄 단위 BM25 | 0 | 1 | 0 |
| AST 구문 단위 BM25 | 1 | 2 | 1 |
| paired-SCIP | 1 | 2 | 1 |

**유효 회귀 테스트는 6/16이지만, 실제 결함 패치를 리뷰하며 그 패치의 결함을 재현한 것은 2/8이다.** 나머지 4개는 정상 패치에서 생성했으며, 별도로 주어진 결함 변형을 구분할 수 있는 회귀 테스트였다. 여섯 개 모두 같은 AnyIO 결함에 관한 결과이므로 여섯 결함을 발견했다는 뜻이 아니다.

AnyIO에서는 구문 BM25와 paired-SCIP이 실제 adapter의 옵션 전달 여부를 가져왔고, 두 방법 모두 원인 설명과 실행 테스트에 성공했다. 이 표본에서는 SCIP만의 우위가 없다. Click은 네 방법 모두 정상·결함을 구분하는 임시 파일의 `w`/`wb` 모드를 가져오지 못했다. 각 방법의 정상·결함 프롬프트가 바이트 단위로 같아, 서로 다른 verdict를 문맥 효과로 해석할 수 없다.

Click 테스트는 존재하지 않는 모킹 대상이나 잘못된 줄바꿈 기대값으로 대조 환경부터 실패했다. 즉, 실행 검증에는 결함 head의 실패뿐 아니라 정상 대조 환경의 통과도 필요하다. primary 실행 96회, 정적 import 거부를 살펴본 별도 사후 실행 32회를 기록했다. 사후 실행에서 추가 유효 테스트는 없었고 원래 점수는 유지했다. 원본 소스 변경은 0이며, 실행 snapshot 8개의 소스는 corrected SCIP index와 일치했다.

상세: Swing 보고서, 집계, 판정 근거.

## 2. 누적 이력 → 결함 메모리 → 현재 diff 재확인

MCR-bench 배포본의 create-react-app #754, scikit-learn #17269, material-ui #46749에서 처음 세 라운드를 사용했다. 라벨을 보지 않는 입력 크기 조건·해시 순위로 선택했다. 3개 PR × 3라운드 × 3조건 = reviewer 27회, 익명화 semantic judge 9회다. 메모리는 이전 모델 출력으로만 만들고 정답은 평가에만 사용했다.

| 조건 | 탐지 micro F1 | 결함·상태를 함께 맞힌 정답 / 13 | 애플리케이션 입력 토큰 합계 |
|---|---:|---:|---:|
| 누적 이력 | 0.250 | 3 | 29,154 |
| 결함 메모리 | 0.240 | 3 | 20,872 |
| 메모리 + 현재 diff 재확인 | 0.167 | 2 | 21,530 |

**메모리는 애플리케이션 입력을 28.4% 줄였고 정확도 개선은 관측되지 않았다.** 시스템 입력까지 포함한 CLI 보고 input tokens의 감소는 약 7.5%다. 28.4%를 그대로 비용·지연 절감률로 읽으면 안 된다.

정답은 고유 리뷰 관심사 7개, 라운드별 상태 등장 13개이며 **New 7, Resolved 6**이다. Open·Reopened가 없어 미해결 유지나 재발 탐지를 평가하지 못했다. 기능 버그 외에 스타일·리팩토링 요청도 포함된다. 조건부 상태 정확도는 탐지한 2~3개에서만 계산되므로 전체 정답에 대한 위 표의 동시 성공 수를 함께 봐야 한다.

judge가 누적 이력 조건의 정규식 설명을 별개의 스타일 정답과 매칭한 한 건은 의심스럽다. 이 매칭을 빼는 사후 민감도 계산에서 누적 이력 F1은 0.250에서 0.167로 바뀐다. 기본 점수는 수정하지 않았으며 **이 결과로 세 방법의 순위를 정할 수 없다.** 같은 계열 모델 judge와 작은 표본이라는 한계가 있다.

또한 일부 입력은 같은 파일의 연속 커밋 diff를 이어 붙여 중간 코드와 최종 코드가 섞인다. 이번 재확인은 현재 diff에 파일이 보이는지 확인하고 다시 판단하도록 지시한 수준이다. 실제 저장소 최종 head의 복원·새 소스 검색·CI 검증을 수행한 조건이 아니다. 일부 라운드의 정답은 이미 해결된 오래된 카드를 제외하므로, 정답과 매칭되지 않는 출력을 모두 환각으로 분류하지 않았다.

상세: MCR 보고서, 기본 결과, judge 민감도.

## 두 아이디어를 연결할 구체적 근거

MCR의 메모리 + 재확인 조건은 material-ui에서 `fs.cp`가 목적지 부모 폴더를 만들지 않는다고 주장했다. 실제 `await fs.cp(swSrc, swDest, { recursive: true });`를 정확히 인용하면서도 잘못된 동작 가정을 했고 다음 라운드에도 Open으로 유지했다.

별도 로컬 Node v24.3.0 미세 실험에서는 부모 폴더가 없어도 `fs.cp`가 복사에 성공했다. 대조한 `fs.copyFile`은 ENOENT로 실패했다. 이것은 역사적 PR 환경이나 전체 CI의 재현은 아니지만, 모델이 한 일반적인 API 동작 단정은 이 환경에서 반증된다. 실행 코드 · 결과

따라서 후속 가설은 **“메모리 카드에 실행 결과와 반증을 붙여, 틀린 지적의 유지와 재등장을 줄일 수 있는가?”**가 적합하다. 정확한 코드 인용은 동작 검증을 대신하지 않으며, 테스트의 실행 실패도 결함 증명을 대신하지 않는다.

다음 실험에는 실제 라운드별 최종 파일 복원, Open·Resolved·Reopened 전이를 포함한 별도 PR 표본, 동일 문맥 예산의 구문 BM25 비교군, 실행 결과로 카드를 철회·수정하는 조건이 필요하다. Click은 먼저 결정적인 producer 문맥과 공통 환경 fixture를 갖춰야 한다. 이 후속 실험은 이번 실행에 포함하지 않았다.

## 실행 무결성과 산출물

- 최종 유효 호출: Swing 16 + MCR reviewer 27 + judge 9 = **52회**, 관측된 도구 호출 **0회**.
- 초기 transport에서 MCP 도구 호출이 발견되어 두 트랙의 최초 batch 전체를 제외하고 보존했다. 제외한 시도는 **13회**(완료 9, 중단 4)이며, 수정 transport에서 원래 입력으로 다시 실행했다. 성공한 진단 호출 3회는 별도다. native 도구 목록이 완전히 없었다는 보장은 하지 않는다.
- 최종 52회 usage: input **561,607**, output **35,964**. cached input **131,072**과 reasoning output **22,609**는 각각 부분집합이며 합산하지 않는다. 무효 시도·진단 usage는 이 수치에서 제외했다.
- 52개 저장 요청의 prompt hash와 raw trace, usage를 통합 감사했다. MCR reviewer 27개의 입력 재구성 검사도 통과했다. 원래 공통 코드·사전 입력·최종 산출물 해시를 대조했다.
- transport·Swing·MCR 하네스 검증 **13개 테스트 통과**. 의미 판정의 소스 검토자는 연구 어시스턴트이며 독립된 blinded human 평가가 아니다.
