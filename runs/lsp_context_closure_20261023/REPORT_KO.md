근거 충분 지적 F1은 기존 C0 **27.5%**, 개선 C1 **30.2%**다. 차이는 **+2.7%p**, PR cluster bootstrap 95% 구간은 -20.0~+28.6%p다.

상속·재정의 여부가 빠진 CharField 사례에서는 명확한 근거 보완과 탐지 증가가 확인됐다. 그러나 전체로는 탐지 1건 증가에 그쳤고, 신뢰구간이 0을 넓게 포함한다. 현재 결과만으로 전면 적용의 안정적인 성능 향상을 주장하기 어렵다. 필요한 연결을 끝까지 확보하고 기존 핵심 소스가 밀리지 않게 하는 선택 정책이 다음 개선점이다.

## F1과 지적의 근거

| 구성 | TP | FP | FN | Precision | Recall | F1 |

| C1 누락 보완 | 8 | 9 | 28 | 47.1% | 22.2% | 30.2% |

F1은 정밀도와 재현율의 조화평균이며 `2TP/(2TP+FP+FN)`으로 계산했다. 결함 리뷰마다 정답 원인 1개와 지적을 1:1 매칭한다. TP는 제공된 코드로 필요한 원인·연결을 입증한 지적, FP는 매칭되지 않은 최종 지적, FN은 찾지 못한 실제 결함이다. 결함본의 보류와 실패도 FN이다. 분모 36은 독립 PR 36개가 아닌 12 PR×3회 반복이다.

FP에는 정상본 오탐뿐 아니라 잘못된 원인 설명, 필수 근거 부족, 중복 지적도 포함된다. **근거 부족으로 매칭하지 못한 지적을 실제로 없는 버그라고 단정하지 않는다.** 정상본에 대한 오탐은 아래에 따로 보였다.

## 실제로 달라진 부분

- N02 Django CharField deepcopy: C0 0/3 → C1 3/3 근거 충분 탐지. C0 세 응답은 CharField가 Field.__deepcopy__를 상속하는지 몰라 보류했다. C1 결함본은 CharField(Field) 선언·전체 명시 멤버 목록(E-CLASS-9cf9175169)·Field 초기화/복사 본문을 공급했고, 세 응답이 해당 근거로 공유 error_messages 변경을 정확히 설명했다. 필요한 연결을 새로 확보해 못 찾던 결함을 찾은 가장 강한 사례다. 이 근거는 첫 응답부터 있었으므로 두 번째 호출에서 새로 발견한 효과로 설명하지 않는다. 정상 방향은 예산 때문에 CharField 목록이 빠져 양방향 성공으로 이어지지 않았다.
- N10 Point와 N11 pytest 표현식은 조건부 로컬 탐지가 각각 2/3 → 3/3으로 늘었다. Point는 팩토리·하위 클래스·distance 재정의 여부를 확보했지만 coordinate args 저장/getter·길이 연결이 빠졌다. 특히 기존 C0에 있던 GeometryEntity/Basic 생성자 일부가 밀려났다. pytest는 compile/evaluate를 확보했지만 expression/expr/Scanner에서 IDENT로 가는 연결은 여전히 빠졌다. 따라서 두 사례 모두 엄격한 TP는 0이며, 실제 결함이 없다는 판정은 아니다.
- N09 Rational은 3/3 → 1/3, N12 Blueprint는 2/3 → 1/3으로 줄었다. Rational 핵심 산술 본문은 유지됐지만 주변 소스가 늘어난 뒤 2회가 추가 연결을 요구하며 보류했다. Blueprint는 Scaffold.__init__/get_root_path 근거가 밀려났고 공개 클래스 연결 등에 대한 보류가 증가했다. 컨텍스트 변화와 응답 변동이 함께 있으므로 이 감소를 특정 원인 하나에 확정적으로 귀속하지 않는다.
- N05 floatformat은 2/3 → 3/3이지만 Decimal 계산에 필요한 함수는 이미 양쪽에 있었다. C0 1회가 Decimal('0.00')의 자릿수를 2개라고 쓰며 2-2=-1로 잘못 계산한 반면 C1은 올바르게 설명했다. 이는 새 코드 연결로 얻은 성공이라고 주장하지 않는다. N03은 입력 소스가 동일하며 양쪽 모두 3회씩 functools.wraps가 예외를 낸다는 잘못된 원인을 반복했다.
- 최종 정상본 오탐은 양쪽 모두 0/36이다. 엄격한 FP 8/9건은 모두 결함본에서 정답 원인과 근거 기준에 매칭되지 않은 지적이다. C0는 잘못된 원인/계산 4건 + 조건부 근거 4건, C1은 잘못된 원인 3건 + 조건부 근거 6건이다. 보류는 49→42로 줄었지만 근거 충분 정상 판정은 6→5, 양방향 성공은 4→2로 줄었다.
- 경계 판정 민감도도 크다. 사전 규칙대로 N05의 잘못된 계산은 TP에서 제외했다. 이를 예외적으로 인정하는 사후 가정을 적용하면 C0 F1은 31.4%, C1은 30.2%가 되어 차이의 부호가 바뀐다. 주 결과는 변경하지 않았으며 grading_sensitivity.json에 이 가정을 분리했다.

## 해석의 범위

실험을 작성한 AI와 별도 AI 검토자가 응답·실제 공급 근거를 읽고 비블라인드로 채점했다. 독립 전문가 평가가 아니다. 같은 12 PR의 이전 누락 분석을 참고해 정책을 설계했으므로 **개발 사례의 개선 확인**이며 미사용 PR·저장소·다른 언어로 일반화하지 않는다. 공개 계약과 고정 입력에 대한 제한된 리뷰이며 실제 제품의 전체 MR 리뷰나 현장의 Python 강점 피드백을 직접 재현하지 않았다.

추가된 근거가 이미 있던 의심을 입증한 경우와 처음 못 찾던 결함을 찾게 한 경우를 구분했다. 모델 응답은 독립 생성됐으므로 동일 소스에서 생긴 차이는 추론·표본 변동을 배제할 수 없다. 후보 철회 프롬프트, 전체 삭제 후 fallback, AST 실행 개요, RL은 이번 변경에 넣지 않았다.
