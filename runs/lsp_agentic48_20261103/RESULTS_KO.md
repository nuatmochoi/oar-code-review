## 평가 형식과 공통 사실

기존 gold witness 40k 선택과 세 조건·두 반복의 실제 final 위치/전달 소스를 합친 추가24k 이내 공통 factpool을 case별로 만들었다. 여섯 판독에 같은 pool을 제공하며 arm 순서 독점을 줄이도록 round-robin으로 온전한 source unit을 넣었다. 공간 초과·동적 환경 불명은 미해결로 기록한다. 이 평가용 소스를 reviewer가 보았다고 처리하지 않는다.

Judge는 source ID enum과 실제 표시 물리 start/end 행을 선택하고 controller가 literal을 추출한다. 핵심 문구는 실제 finding의 선택 필드 전체를 추출한다. 문자열 재작성 실패를 줄이는 wire 변경이며 semantic label, 일대일 target matching, 원인·유효 보고 기준은 이전과 같다. 인용 기계 검증은 의미적 진위·배포 환경·실행 도달성을 보장하지 않는다. 모든 조건에 새 judge를 적용했고 인간 검토는 0건이다.

과거 B2 원문 평가의 원인/유효 F1은 10.79%/10.31%였으며 별도 참고값이다. 새 FIXED는 공통 factpool·새 span wire로 fresh 평가했으므로 두 숫자의 차이를 reviewer 개선으로 해석하지 않는다. 기존 정답 366개·전체 기능385개·source 지지 보조116개 및 사전 goldseal은 변경하지 않았다.

본문 확보·연결된 조건 조회·반박 상태 반영·정확한 최종 설명은 서로 다른 측정이다. 실행 로그와 원인 전이를 확인하기 전에는 F1 차이만으로 검증·반박 기전을 확정하지 않는다. 교정 분모가 0이면 교정률은 추정 불가로 남긴다.

동일 상한은 초기+planner+final 3회/120k provider 토큰·source12k·native48회/180초·active wall900초다. 계획만 초기 claim/finding의 온전한 파일 diff section을 선택하며 최종 reviewer는 전체 원본 diff를 받는다. 모델 전 예산 검사에서 planner 가능한 55/96회 외의 보존 사례도 전체 결과에 남겼다. 완료 subset은 사후 실행 진단이다.

추가 조회−같은 본문 추가 검토는 조회·추가 본문·길어진 final 입력을 포함한 묶음의 효과다. 실제 토큰/source 양을 맞춘 대조군은 없으므로 질문 선택 정책만의 독립 효과로 해석하지 않는다. 동일 상한과 실제 사용량을 함께 비교한다.

총3회 호출이므로 추가 조회는 한 차례의 계획된 acquisition round다. 새 답을 본 다음 두 번째 planner가 새 질문을 만드는 적응적 다회 루프는 실행하지 않았다. 원래 본문에서 반박 후 후속 소비 경로를 계획하는 것과 새 답 이후 반복 재탐색을 구별한다.

이 48개는 이미 개발·분석에 사용한 사례이며 일반화나 미사용 평가 증거가 아니다. Clean PR 대조군이 없어 clean-PR 오탐률은 계산하지 않았다. 확인 오탐 수와 미해결을 구분한다. LSP 자체의 최초 사용은 기여가 아니며 [선행 Go 코드 리뷰 연구](https://arxiv.org/html/2606.01859v1)와 기여 재검토를 함께 본다.
