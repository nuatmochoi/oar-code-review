# 출력 소비 경로 보충 개발 실험 결과

2026-10-02. 같은 4개 PR에 대해 B와 O를 새로 호출한 48건 비교를 완료했다. 출력 경로 보충은 근거 있는 회귀 검출을 2/12에서 5/12로 늘렸지만, 양방향 정답 쌍은 1/12에서 2/12에 그쳤다. 효과는 exception chain과 skip 보고 사례에 집중됐다. 기본 B를 대체할 근거는 아직 부족하다.

## 설계와 범위

- B: 직전 state 실험의 기본 소스·공통 입력·정적 관측을 그대로 사용하고 모델 응답은 새로 생성했다.
- O: 사람이 지정한 출력 소비 경로의 선언에서 실제 Pyright LSP definition을 조회하고 관련 소스를 보충했다. 클래스의 하위 메서드 선택과 부분 추출은 AST 기반이다. 자동으로 출력 경로를 발견하는 정책이나 LSP만의 인과 효과를 검증한 실험은 아니다.
- 이미 본 pytest PR 4개 × 정상/회귀 두 방향 × B/O × 3회 = 논리 48건, 새 물리 호출 48건. gpt-5.6-sol, low, workers 4, 재시도 0. 모델 seed는 통제하지 않았다.
- 각 조건의 소스 최대 1600토큰, 정적 관측 최대 400토큰. 공통 DIFF/계약은 같은 입력이며 이 수치는 전체 프롬프트 토큰 예산이 아니다.
- B의 보호 대상 변경 head 소스는 보존했다. 다른 단위는 O에서 교체되므로 기존 B 전체에 단순히 추가한 비교는 아니다.
- 모델 입력 전에 소스·프롬프트·프로토콜·채점 기준을 동결했다. 모델에는 숨긴 실행 witness를 제공하지 않았고, 작성자가 보이는 근거와 공개 계약으로 비블라인드 채점했다.
- 기존 공식 snapshot과 직전 단계의 검증된 실행 witness를 재사용했다. 이번 단계에서 runtime witness를 다시 실행하지 않았다.

| 정상 방향 오탐 | 0/12 | 0/12 |
| 정상·회귀 모두 정답인 쌍 | 1/12 | 2/12 |
| 근거 있는 전체 방향 정답 | 3/24 | 7/24 |

검출 분모는 회귀 방향, 오탐 분모는 정상 방향이다. 근거 없는 정상 판정도 정답으로 세지 않았다. O의 보류 감소에는 근거 없이 확정한 응답이 포함되므로 그 자체를 개선으로 해석하면 안 된다.

|---|---|---:|---:|---|

같은 반복 번호의 양방향 정답 쌍 비교에서 J01 반복2가 추가로 성공했고 손실 쌍은 없었다. 반복 번호는 동일 난수 seed를 뜻하지 않는다. 4개 PR의 반복이지 독립 12개 PR이 아니므로 통계 우월성이나 다른 저장소 일반화를 주장하지 않는다. 직전 단계 B의 검출 4/12와 이번 새 B 호출의 2/12 차이도 응답 변동이 작지 않음을 보여준다.

## 근거 판정과 추출기의 한계

J01은 별도 exception chain entry, 순서, cause 관계와 section 보존에 한정해 인정했다. 초기 예외 이름이 출력 문자열에서 완전히 사라진다는 주장은 인정하지 않는다. 출력에 소스 코드가 포함되어 예외 이름이 남을 수 있다. 전체 runner dispatch와 모든 기본값 동작까지 입증한 결과는 아니다.

J03은 runxfail 분기의 pass 뒤 elif가 marked-skip 위치 보정을 막는 직접 코드 계약 위반을 인정했다. 정상 방향에서 정확한 decorator 위치를 입증하려면 getfslineno와 실제 receiver 연결 등이 추가로 필요하다. 전체 터미널 처리와 hook 연결이 인증된 것은 아니다.

J02의 정상 확정 응답은 B 1건, O 2건 모두 실제 수집 경로를 입증하지 못해 정답에서 제외했다. 조건별로 같은 기준을 적용했다.

J04에서 O는 정상 3건 모두 정상으로, 회귀 3건 모두 issue로 응답했다. 하지만 보이는 부분 소스에는 `marker.name`을 `name`에 대입하는 문장, fixture 목록 등록 append, 출력 available 목록 append가 빠져 있다. 이름 생성과 underscore 필터만으로 그 이름이 실제 출력에 도달한다고 단정할 수 없다. 회귀 issue 3건과 정상 판정 3건 모두 성공에서 제외했다. 숨긴 witness는 label 검증용이며 이 증거 공백을 메우는 데 쓰지 않았다. 호출 실패가 아닌 컨텍스트 연결 누락이다.

큰 함수를 500토큰으로 자를 때 키워드와 제어 흐름 헤더를 우선하는 현재 방식은 중요한 대입문을 누락시킨다. 남은 소스 예산이 있어도 개별 함수의 부분 추출 제한 때문에 연결이 빠질 수 있다. J01 회귀 방향의 repr_excinfo 1개 단위는 전체 소스 예산 때문에 추가되지 못했다.

## 운영 검증과 실제 조회량

- 48건 모두 transport/schema 유효, 모델 도구 호출 0, 재시도 0, 누락 0. 입력 identity, 보호 소스, workspace hash, freeze/preparation seal 모두 검증을 통과했다.
- 이번 v2 출력 경로 준비에서 native definition 24회. 공통 B definition 96회는 직전 단계 trace를 재사용했으며 이번 신규 조회로 세지 않는다.
- 이전 v1 준비에서 native 조회 22회 후 잘못 지정한 `summary_skips` 메서드 때문에 제외했다. 모델 호출은 0회이며 파일을 보존했다. v2에서는 `short_test_summary`로 수정했다. 이번 작업의 실제 준비 신규 조회 합계는 46회다.
- 8개 방향 모두 O 소스가 B와 달랐다. 총 추가 34단위, 제거 52단위, budget으로 추가 차단 1단위. 단위마다 길이가 달라 수량 자체는 정보량 비교가 아니다.
- 인용한 issue 파일·행 존재를 확인했지만 별도의 localization accuracy는 측정하지 않았다.

## 다음 구현 과제

기본 B를 유지하면서, 출력 경로 소스를 추가할 때 필수 데이터 연결을 함께 보존하는 추출기를 개발한다. 우선 fixture 이름에 대해 생성 → marker.name 선택 → FixtureDef/등록 목록 → available 목록 → 출력 필터의 대입·호출 인자·반환 연결을 묶어 공급한다. 필요한 연결이 예산에 들어가지 않으면 일부만 넣고 확정시키지 않고 미해결로 표시해야 한다.

이 4개 사례에서 연결 보존을 점검한 뒤, 자동 선택 규칙을 동결하고 새 PR로 비교해야 한다. 이번 수치는 사람이 결과를 본 뒤 선택한 경로를 공급한 개발 결과다. 최신 논문의 충실 재현 또는 자동 LSP 정책의 성능 향상으로 제시하지 않는다.
