# 실제 LSP 조회 우선순위·컨텍스트 실험

기존 11 PR 계열에서는 **B(변경 함수와 공개 진입 후보 우선)가 가장 유망한 기본 후보**였다. 양 방향 모두 근거 있게 판정한 반복 쌍은 A 7/33, B 12/33, C 10/33이다. 그러나 결함 검출은 A 23/33에서 B·C 21/33으로 줄었다. 따라서 B가 전반적으로 우월하거나 C의 추가 조회가 항상 도움이 된다고 결론 내리지 않는다.

## 구현과 공정 비교

| 조건 | 실제 조회 정책 |
|---|---|
| A | 기존 실제 Pyright LSP 컨텍스트와 trace 재사용, 모델 응답은 새로 호출 |
| B | 변경 함수·변경 줄 호출·공개 호출명에 대응하는 진입 후보부터 native definition 조회 |
| C | B + receiver attribute/getter·모듈에 선언/수입된 global 이름과 import 근거 조회 |

실제 Pyright 1.1.414 stdio의 `textDocument/definition`을 사용한다. AST는 호출 위치·소스 단위·순서를 정하는 데 쓰이며, 정의 결과를 AST 해석으로 대체하지 않는다. LSP 반환은 정적 후보이고 런타임 dispatch 증명은 아니다. 실제 native getter/global 반환과 근거 추출을 확인하는 통합 점검을 통과했다.

소스 1600 + 정적 관측 400 reference tokens, prefix 800, snapshot당 native 질의 12회, 깊이 cap 3을 유지했다. 실제 기존 사례에서 관찰된 질의 깊이는 최대 1이다. B/C의 일반적인 깊이 확장 구현은 A와 완전히 같은 코드가 아니지만 이번 고정 입력에서 깊이 2 이상 질의는 없었다. source 단위를 통째로 넣는 방식 때문에 큰 함수는 예산 밖으로 밀릴 수 있다. 본문 부재는 동작 부재의 증거가 아니다.

11계열 × 2방향 × 3조건 × 3반복 = 198 논리 평가, 198 새 물리 모델 호출. gpt-5.6-sol low, 리뷰 중 도구 0, 재시도 0. 반복 번호는 실행 식별자이며 provider seed를 통제한 실험이 아니다. 같은 arm 입력을 반복 호출했고 과거 응답은 재사용하지 않았다. A/B 결과를 기록한 후 C를 실행했으며 C 정책은 A/B 결과를 보기 전에 고정했다.

## 조회와 비용

최종 snapshot trace의 질의 수는 A/B/C 각각 264회다. A는 이전 trace 재사용, B/C는 각각 새로 요청했다. callable 정적 후보가 나온 질의는 51/61/62회였다. C의 source-unit 위치 반환은 137회였지만, 위치 반환·본문 삽입·인과 증명은 서로 다른 단계다. 조회 수 확대만으로 결함 검출은 늘지 않았다.

준비 단계 C0에서 builtin 참조가 extra slot을 소비하는 문제를 모델 호출 0회 상태에서 수정했다. 초기 packet·trace·freeze를 보존했으며 최종 A/B 입력은 그대로다. 최종 B264 + C264 외에 폐기된 C0 264회의 준비 질의도 별도로 발생했다. 통합 점검 질의는 별도다.

reference evidence token 예산과 provider usage 토큰은 서로 다른 지표다. native 질의의 오류 응답은 0회다. 공유 설정 파일의 `autoSearchPaths` 항목에 대한 config warning은 trace에 남아 있으며 클라이언트의 python.analysis 설정도 전달했다. warning을 질의 성공 여부와 혼동하지 않는다.

## 다음 개선의 우선순위

1. **B를 다음 실험의 기본 후보로 삼는다.** 양방향 판정 개선과 결함 검출 감소를 함께 추적하고 새 사례에서 다시 확인한다.
2. **큰 함수와 public→helper 인자 연결을 먼저 해결한다.** E01/E02/E11은 조회 순서만 바꿔도 필요한 본문·binding을 못 넣는다. signature, 인자 추출, 변경 branch, 호출 인자 주변의 범위 근거를 명확한 부분 코드 표시와 함께 넣는 다음 ablation이 필요하다.
3. **C는 미해결 receiver·alias·global 의존성에만 조건부로 사용한다.** 남은 질의/소스 예산에 필요한 source unit이 실제로 들어갈 때만 실행하도록 비교한다. 현재 C는 항상 실행하는 정책이며 조건부 정책의 성능은 아직 검증하지 않았다.
4. **상태·인용 검증을 강화한다.** 관측을 unknown으로 쓰고도 no_supported_issue를 반환하는 불일치와 evidence ID 오류를 측정한다. 정적 후보에 런타임 의미를 덧붙이거나 틀린 ID를 자동으로 교정하지 않는다.

## 재현 자료

고정 프로토콜, 입력·코드 해시, 전체 감사, 검토 근거, 결과, 검증. packets/에 고정 입력, lsp_traces/에 실제 native 응답, raw/에 원본 모델 응답이 있다. 기존 run은 수정하지 않았다. 자연 결함 도입 PR, RL 학습, 논문의 완전 재현 또는 통계적 우위를 주장하지 않는다.
