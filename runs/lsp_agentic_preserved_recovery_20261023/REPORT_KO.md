Agentic 탐색은 필요한 상속 연결을 보완한 사례에서 실제로 도움이 됐다. 그러나 전체 엄격 F1의 증가는 2.2%p에 그쳤고 신뢰구간이 0을 포함한다. 재현율은 19.4%→22.2%로 올랐지만 정밀도는 58.3%→53.3%로 낮아졌다. 현재 근거는 제한된 개선 가능성을 보여주며, 전반적으로 우수한 구성이라고 확정하기에는 부족하다.

F는 첫 리뷰 결과와 무관하게 고정 정책으로 추가 조회하고, G는 첫 리뷰의 구조화 요청·미확인 연결을 우선해 추가 조회한다. 양쪽 모두 기존 전체 초기 소스를 보존한 뒤 두 번째 리뷰를 수행한다. 모델은 gpt-5.6-sol, low이며 모델 자체 도구 호출은0회다.

- 2순위 — 남은 조회 예산 안에서 필요한 연결을 끝까지 따라가기. 새 클래스 inventory가 생기면 보류 중인 compile·_print·__len__·생성자 요청을 다시 해석하고, 무관한 생성자·넓은 references 확장보다 우선한다. N11은 최종 소스923토큰으로도 compile 본문을 놓쳐 용량보다 조회 순서 문제가 드러났다. N10은 용량 제한도 함께 있어 순서만 바꾸면 해결된다고 단정하지 않는다.
- 3순위 — 근거와 판단의 안정성 검증. 첫 판단에서 입증한 주장·가정·미확인 연결을 분리해 기록하고, 관련 반증 없이 무관한 export 불확실성 때문에 철회되는 패턴을 줄이는 실험을 한다. 잘못된 wraps 예외 위치나 숫자 계산은 좁은 실행 probe 또는 독립 검증기로 확인하는 조건을 별도 비교한다. 이번에는 이러한 실행 검증을 추가하지 않았다.
- 검증 순서 — 위 변경을 하나씩 고정한 별도 arm으로 같은 사례에서 절제 비교한 뒤 미사용 Python PR과 다른 언어로 확장한다. 현12개는 이미 개발에 사용했으므로 새 모집단에서 독립 판정이 필요하다. 후속 병렬도 실험은 모델2→3→4의 작은 사전 파일럿으로 실패율과 성공 처리량을 비교하고 본실험 전에 고정한다.
