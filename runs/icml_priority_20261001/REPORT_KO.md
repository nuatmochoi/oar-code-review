# ICML 아이디어 코드 리뷰 실험 결과 — 2026-10-01

정의 탐색(D), 자체 재검토(SELF2), critic 검토(CRITIC)를 BM25(L)와 비교한 로컬 추론 실험이다. gpt-5.6-sol / reasoning low, 증거 1,600 reference tokens, 같은 최종 리뷰 규칙을 사용했다. RepoNavigator 학습 모델이나 논문 전체를 재현한 결과는 아니다.

|---|---:|---:|---:|---:|---:|

결함의 원인만 맞힌 조건부 경고는 근거 있는 검출에서 제외했다. 모델 입력에 실제 배포 조건이 보여야 한다. 기권은 안전 판정으로 세지 않았다.

결함의 원인만 맞힌 조건부 경고는 근거 있는 검출에서 제외했다. 모델 입력에 실제 배포 조건이 보여야 한다. 기권은 안전 판정으로 세지 않았다.

새 사례의 BM25도 H01·H02의 변경 원인은 맞혔지만, 실제 배포 인자가 없어서 조건부 경고로 분류했다. H03·H04는 인자는 보였으나 진입 함수가 빠져 기권했다. 따라서 0/4는 일반적인 코드 결함 발견 능력이 없다는 의미가 아니라, 이 실험의 실제 배포 조건까지 입증하는 기준을 통과하지 못했다는 의미다.

## 해석과 우선순위

1. **정의 탐색을 우선 검토**한다. 새 사례에서 실제 배포 진입 함수와 인자가 보이면 결함을 판정할 수 있었지만, 더 많은 컨텍스트가 정확한 범위 판단을 보장하지는 않았다. D의 H01 안전 조건은 `vertexai=True`인데도 `False`를 가정해 경고했다. 개발 F02에서도 실제 -1 설정이 유지됨을 인정하면서 다른 예산을 가정해 오탐했다.
2. **추가 검토는 선택적으로 검증**한다. 개발 F07의 실제 `ab ab`와 리뷰가 가정한 `b ab` 차이를 SELF2/CRITIC이 바로잡았다. 반면 빠진 진입 함수나 인자는 같은 입력의 재검토로 채울 수 없다. 개발 F08에서 critic은 보이지 않는 producer 헤더의 부재를 가정한 경고를 지지했고, 안전 world에서는 기존 안전 판정을 기권으로 바꿨다. 비용 대비 이득과 오탐 감소를 구분해야 한다.
3. **V1 후보 순위 선택은 보류**한다. 이번에는 후보 순위 arm을 실행하지 않았다. 먼저 검색과 실제 범위에 대한 판단을 안정화하고, 올바른 후보가 후보군에 포함되는지 측정해야 한다.

D와 CRITIC의 조합은 이번 실험에서 측정하지 않았다. 다음 검증 후보는 D에 실제 배포 인자·분기·결과를 명시적으로 연결하는 검토를 더하는 것이며, 효과를 이미 입증한 것으로 해석하면 안 된다.

논리적 비용에는 공유한 L 최초 리뷰를 각 검토 조건에 다시 포함했다. 물리적 호출 수와 중복 합산하면 안 된다. provider usage에는 Codex의 시스템 입력도 포함된다. 검색 예산 1,600은 reference tokenizer의 증거 텍스트 한도이며 전체 provider 입력 토큰이 아니다. cached 입력은 입력 tokens의 일부다. 금액으로 환산하지 않았다.

본실험은 계획 120회 중 119회 호출했고 119회 모두 transport·JSON schema가 성공했다. H04 unsafe critic은 초기 issues가 비어 있는데 issue_index=0을 생성했다. 관계 검증에서 차단돼 마지막 수정 호출 한 번을 실행하지 않았고, 최종 리뷰는 79/80개다. 해당 실패를 분모에 남겼다.

새 witness 32회는 전부 예상 결과와 일치했다. 각 함수의 원본 AST 본문을 실행하되 외부 provider/UI 경계는 fixture로 대체했다. 정책·입력 해시, 증거 한도, 응답 schema·인용 ID·status/list·critic 이슈 범위 검사와 관측된 도구 호출 수를 감사했다. 자세한 무결성 결과는 audit.json에 있다.

실행기 오류 두 가지를 공개한다. 처음 결과 디렉터리가 없어 12회 시도의 응답/trace/usage를 보존하지 못했다. 해당 입력과 오류 로그는 infrastructure_failed에 보존했고, 성공 여부와 토큰 비용은 알 수 없다. 이어 macOS에서 critic/CRITIC 이름이 충돌해 수정 호출이 건너뛰어졌다. 파일 접미사만 critic_final로 바꾸고 빠진 수정 호출을 채웠다. 기존 응답은 재호출하지 않았다. 원래 freeze와 수정 freeze를 모두 보존했다. 검색 정책·프롬프트·schema는 바꾸지 않았다. 본실험 호출 외에 앞선 12회 시도가 있었으므로 총 시도 수는 본실험+12회다.

## 해석의 한계

개발 6쌍은 이미 사용한 사례다. 새 4쌍도 같은 BrowserUse·ComfyUI 저장소와 이전 배경 파일에서, 다른 함수에 단순 변경을 주입한 통제 사례다. 새 함수이지만 독립 저장소 holdout이나 자연 PR benchmark가 아니다. 사례 수가 작고 작성자가 응답과 arm 이름을 보며 판정했다. 단일 모델·단일 실행이므로 통계적 유의성이나 일반 성능 향상을 주장하지 않는다.

이 실험은 고정한 배포 입력에서의 실패를 판정한다. 실제 제품 전체를 검토할 때는 다른 지원 입력도 유효한 리뷰 범위일 수 있으므로, 여기서 조건부 경고로 제외한 일반적 결함을 제품 리뷰에서도 자동으로 오탐 취급하면 안 된다.

AST 정의 해석은 명시적 import·같은 파일·확인한 생성자로 제한했다. Pyright, 타입 추론 전체, 함수 반환 객체, 동적 dispatch, 고차 함수로 전달한 handler를 추적하지 않는다. 내부 정적 탐색은 모델이 보는 예산 밖의 소스를 검사할 수 있으며 모델에 제공한 최종 소스만 예산에 포함된다. 정적 연결은 런타임 실행의 증명이 아니다.
